# Module: System Design Fundamentals

**Category:** Backend · **Typical duration:** 1 week dedicated, ongoing practice after · **Prerequisite modules:** [APIs & Backend Services](apis-and-services.md), [Databases & Caching](databases-and-caching.md)

## Goal

Reason about a system at the whiteboard level — scaling, reliability, and tradeoffs — well enough to design one in an interview and to make real architecture decisions on the job.

## Core topics

- [ ] [Monolith vs microservices](../../../engineering/concepts/backend/architecture/monolith-vs-microservices.md); when each is the right call
- [ ] [Load balancing](../../../engineering/concepts/networking/load-balancing.md), [horizontal scaling](../../../engineering/concepts/backend/architecture/horizontal-scaling.md), API gateways
- [ ] Caching layers, CDNs, queues, and [idempotency](../../../engineering/concepts/backend/api/idempotency.md)
- [ ] Common design patterns: repository, factory, strategy, adapter
- [ ] Back-of-envelope capacity estimation
- [ ] Practice: design 4–6 systems end to end (requirements → architecture → data flow → scaling → failure modes)

## Resources

- A free, widely-used "[system design](../../../engineering/concepts/backend/architecture/system-design.md) primer" (community-maintained, covers load balancing through caching through queues)
- A book on designing data-intensive applications for the concepts behind the interview answers

## Milestone deliverable

A one-page design doc (context, options considered, tradeoffs, decision) for the architecture of your own portfolio capstone project.
